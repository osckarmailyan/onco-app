# События интерфейса

Внешняя аналитика в текущем MVP не подключена. Компонент `AnalyticsEvents` и `trackAnalytics` отправляют только локальное браузерное событие `oncoexperts:analytics`. Нет сетевой отправки, cookie, localStorage, идентификаторов посетителя, журналирования или сохранения событий. Это точка подключения одного согласованного провайдера, а не уже работающая статистика посещений.

Разрешённый payload: `{ event, page, placement }`. Все три поля ограничены списками. Имя, email, телефон, текст вопроса, диагноз, банковские данные, ID записи, URL с параметрами и платёжный токен не передаются. На `/admin`, `/result/*`, API и неизвестных путях событий нет. Фильтр ограничивает путь, но не определяет внутреннюю ошибку страницы на разрешённом публичном пути. У `/success` разрешён только `payment_success` после проверенного ответа API; сам переход по redirect не считается оплатой.

Подготовлены: `page_view`, `cta_click`, `booking_start` (открытие страницы записи), `contact_click` (открытие почтового клиента, не отправка письма), `booking_form_submit` (отправка включённой формы), `payment_redirect`, `payment_success`. Два последних события относятся к подготовленному встроенному сценарию; при ручных счетах ЮKassa они на сайте не возникают. При email-согласовании отправку письма и оплату по индивидуальной ссылке контролирует оператор в почте и кабинете ЮKassa.

Пример подписки в утверждённом адаптере:

```js
window.addEventListener("oncoexperts:analytics", ({ detail }) => {
  // Передать только detail утверждённому провайдеру после проверки правовых оснований.
});
```

Перед подключением внешнего сервиса определить оператора, регион обработки, согласия/основания, срок хранения, условия провайдера и обновить политику. Не добавлять автоматическую отправку форм, query string или персональных параметров. В режиме разработки события можно наблюдать этим же локальным обработчиком; пользовательские данные в console не выводятся.

События — точка интеграции, а не финансовый реестр или уникальный учёт клиентов. `payment_success` защищён от повторных опросов в пределах одного mount; повторное открытие оплаченной страницы может повторить событие. Для будущей статистики конверсий согласовать дедупликацию у провайдера без передачи личных и платёжных данных.
